# Mine

Conventions for the `mine` UI component family under `resources/views/components/mine/`.

## Brand logo color comes from the active theme variable

The brand logo is rendered inline by `<x-mine.brand-logo>` (never as `<img>`), with `fill=currentColor` driven by the `mine-logo` `@utility` (`color: var(--mine-btn-primary-bg)` in `mine.css`).

Do not point at `resources/images/logo.svg` via `<img>` — it had a hardcoded `#173B67` fill that cannot react to theme changes.

The favicon follows the same rule: `public/favicon.svg` (a cropped copy of `resources/images/logo.svg`) is only the template and the unknown-slug fallback — the served icons are the per-theme files in `public/favicons/<slug>.svg`, each with its theme's `mine-btn-primary-bg` fill, regenerated by `php artisan themes:favicons` (re-run it whenever a palette's primary color changes). `x-mine.theme-vars` emits the `<link>`, so the tab icon tracks the same theme resolution as the logo; there is no empty `.ico` fallback.

## Toast state lives in the JS bundle

The toast's Alpine factory is registered as `Alpine.data('mineToast', …)` in `resources/js/app.js`; the component passes its `position`/`duration` props as factory arguments (`x-data="mineToast(@js($position), @js($duration))"`). Keep the maps and methods out of an inline `x-data` — inline factories re-serialize the whole toast implementation into every HTML response.

Toasts are navigation-proof inside the factory too: every toast carries an absolute wall-clock `expiresAt`, `addToast`/dismiss persist the surviving list to `sessionStorage` (`mine-toasts`, capped), and `init()` restores unexpired toasts with their remaining time on every mount — so a toast survives `wire:navigate`, full reloads, and back/forward in either layout. Expired toasts are filtered on restore (never resurrect them), and persistence stays in the factory as the single choke point — never in the dispatching callers.

## Navigations never serve stale data

- Links use plain `wire:navigate` — **no `.hover` anywhere**: hover-prefetch caches the destination HTML for 30 seconds and would swap it in on click after data changed on another page (mark a task done, sweep the mouse over the nav, click — the pre-mutation page comes back).
- `resources/js/app.js` owns one `livewire:navigate` listener: when a back/forward traversal (`detail.history && detail.cached`) lands on a different page than the one rendered, it cancels navigate's in-memory snapshot swap and reloads instead — history navigation always renders fresh server HTML. Same-page fragment traversals (skip link) keep Livewire's scroll restore: their destination path+query equals the rendered page. Every island page is covered by this one listener; add new pages knowing Back/Forward is always fresh.

## Pagination

- The paginator is the project-owned view `resources/views/mine/pagination.blade.php`, reached via `{{ $this->items->links('mine.pagination') }}` — **never** a published vendor override (a Livewire upgrade can clobber `resources/views/vendor/*`; the old override is gone).
- The bar renders **only when `hasPages()`** and carries its own `mt-4 sm:mt-6` — no caller wrapper (an always-rendering wrapper leaves its margin behind on single-page lists). Inside the view, the bar is wrapped in `<x-mine.animate>` (again within `hasPages()`, no `wire:key`) so it reveals on first appearance and stays anchored across island flips. It sits inside the island so `gotoPage` re-renders the list only.
- A11y invariants: the `<nav>` is named `aria-label="{{ __('Pagination') }}"`; the icon-only desktop Previous/Next buttons **and their disabled states** are labelled `__('Previous')`/`__('Next')` (icon-only controls fail axe's button-name rule — same contract as the calendar/datepicker month-nav); the current page keeps `aria-current="page"`; the ellipsis separator is `aria-hidden`.
- Locale rules: logical padding only (`ps-`/`pe-`, never locale-conditional `pl-`/`pr-` pairs); the arrow pair swaps with the writing direction in one place; digits go through one `$num` closure (`PersianNumber::convert` in fa); the range summary hides when `firstItem()` is null (an out-of-range `?page=` renders no broken "Showing to of" text).
- `app.css` `@source`s `resources/views/mine/*.blade.php`, so views placed there ship their utilities in the bundle (css.md).

## Nested UI components are anonymous Blade, not Livewire

- Nested components are anonymous Blade only, under `resources/views/components/mine/` — the `x-mine.*` tag auto-resolves there with no PHP class.
- No class-based components in `app\View\Components`, no `@include` partials.
- Each component has a `mine/<name>/index.blade.php` entry point plus role-named sub-blades (e.g. `input/label.blade.php`, `dropdown/trigger.blade.php`).
- State that needs reactivity belongs on the page component, not a nested Livewire component.

## Accessibility contracts live in the components

- `alert` picks its `role` from the variant — `danger`/`warning` → `alert`, `success`/`info` → `status` — through attribute merge, so a caller can override it.
- Fields own their error a11y wiring: `input`/`textarea` set `aria-invalid` + `aria-describedby` on the control, `select` on its listbox wrapper, `datepicker` on its trigger button — all pointing at the error `p`, whose `id` is the field id + `-error` and whose `role` is `alert`.
- A labelless `input` names itself from its placeholder (`aria-label="{{ $placeholder }}"` when there's no label) and a caller-passed `aria-label` always wins — axe gates placeholder-only inputs; the searchable `select`/`datepicker` search inputs pass their own `aria-label` explicitly (same `Search...` key as the placeholder).
- `Reicon` renders `aria-hidden="true"` by default — decorative unless a caller passes an explicit label.
- `calendar`/`datepicker` month-navigation buttons are labelled `__('Previous')`/`__('Next')` — icon-only nav fails axe's button-name rule.
- `progress` names its bar `aria-label="{{ __('Progress') }}"` — `role="progressbar"` requires an accessible name; no caller overrides it yet.
- Icons/graphics never become the accessible name: `brand-logo` takes `aria-label` from the caller (header passes `config('app.name')`).
